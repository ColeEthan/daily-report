# 工作日报

一个无需账号的静态日报工具，可部署到 GitHub Pages。记录仅保存在当前设备、当前浏览器中。

## 使用

- 选择记录日期，填写姓名、时间和工作内容，点击“添加记录”。历史日期也可以补录。
- 工作内容支持回车换行；电脑可用 Ctrl / Command + Enter 提交。中文输入法选字不会提交。
- 点击记录旁的“编辑”修改内容。取消编辑会保留原记录。
- 未提交的输入按日期自动保存为草稿，刷新后可继续编辑。草稿不会自动包含在汇报中。
- 跨夜工作勾选“次日结束”；只填开始时间或完全不填时间也可以。
- 时间旁的“现在”可填入当前时刻（仅用于今天）；选择开始时间后，点 15 分钟、30 分钟、1 小时或 2 小时会计算结束时间，跨午夜自动勾选“次日结束”。重复点时长按开始时间重新计算，不会累加。
- “＋30分钟（累计增加）”会在当前结束时间上再增加 30 分钟；尚未填写结束时间时，从开始时间加 30 分钟。例如先点“30分钟”，再点“＋30分钟”就是 1 小时。可连续累加，刷新后也能接着累加；再点固定时长则重新从开始时间计算。
- 新增有结束时间且不跨夜的记录后，下一条会接续该结束时间，仍可手动调整。“清空时间”可保留工作内容并移除时间；编辑已有记录不会触发自动接续。
- 点击“生成汇报”后复制。自动复制失败时，可在弹窗内手动全选复制。
- “备份与恢复”可导出全部日报、姓名和草稿，或导入 JSON 备份。换手机、换浏览器或清除网站数据前请先备份。

## 导入与数据保护

- 导入前显示合并预览，确认后才写入；不会按日期直接覆盖已有日报。
- 同一编号、相同内容的记录重复导入会跳过；同一编号的不同版本会作为两条记录保留。
- 同日姓名不同则保留本机姓名。同日草稿冲突时保留本机草稿，并在预览中明确提示；备份文件中的冲突草稿仍需自行保留。
- 从备份恢复的编辑草稿会转成新记录草稿，避免覆盖本机记录。
- 写入失败时保留当前输入并显示提示；仍可导出包含当前输入的备份。
- 多个页面同时打开时，浏览器互斥锁只允许一个页面编辑；其他页面可以查看和导出，不能写入或导入。关闭编辑页面后，刷新另一个页面即可继续编辑。检测到未更新的旧版页面写入时，仍会拒绝覆盖并提示备份。
- 不支持互斥锁、锁请求失败或非安全浏览环境下保持只读，不退回存在并发覆盖风险的保存方式。请使用支持 Web Locks 的新版浏览器，通过 HTTPS 或本地预览服务打开。
- 存储空间不足时仍可打开历史列表、删除记录或清空当日。清理会尝试一次保存清理后的记录与当前草稿；若仍无法保存，原记录和当前输入均保留。
- 导入时，已提交记录的时间关系与正常录入使用相同校验；尚未填完的草稿仍可导入。已有本机记录中的异常时间会以“待核对”文字完整保留，编辑时间后可修正，不会导致全部数据无法读取。
- 数据损坏时停止正常写入。可导出原始数据留存，或导入有效备份；替换前会先另存无法读取的原始数据。如果无法留存，则不会替换。

## 从旧版升级

旧版 `daily_report` 和 `daily_report_name` 会被读取并转换为新版结构；原始键保持不变。新版写入独立的 `daily_report_v2` 键，包含按日期保存的姓名、记录和草稿。

旧版只有一个全局姓名，所以首次迁移时各历史日期继承该姓名；不能恢复旧版未保存的历史姓名。旧版异常时间文本按原样保留，编辑时间后可改为结构化时间。

升级应保持原网址与浏览器，以便读取旧数据。旧版页面无法读取新版记录，回退前请先导出新版备份。

本次修复继续使用 `daily_report_v2`，无需手工转换数据。发布后请关闭所有旧版日报页面再重新打开，确保各页面都使用互斥保存机制；已加载的旧脚本不参与新版本的锁协调。

## 开发与验证

无需安装依赖或构建。`index.html`、`core.js` 和 `app.js` 应放在同一发布目录。

- `core.js`：数据校验、旧版迁移、时间和汇报格式、备份解析及合并。
- `app.js`：页面交互、草稿保存、存储异常保护及复制回退。
- `tests/`：数据回归测试和使用 DOM 替身的交互逻辑测试，不代替真机浏览器测试。

使用 Node.js 运行：

```sh
node --check core.js
node --check app.js
node --test tests/*.test.cjs
```

页面使用现代浏览器原生 `<dialog>` 和 Web Locks API。锁在页面离开时释放，从浏览器返回缓存恢复后会重新申请；重新获得锁后重新读取已保存数据，未保存输入则继续留在页面等待保存或导出。发布前建议在实际使用的手机浏览器中确认时间选择器、文件下载与复制权限表现。
